# 九曲云档 · 黄河文化分布式数字档案

面向黄河文化遗址与文物的移动端数字档案应用，基于 HarmonyOS / ArkTS 开发，提供遗址浏览、检索筛选、收藏标签、个人笔记、浏览足迹、知识图谱、桌面服务卡片与多设备数据同步。

## 功能概览

- 遗址档案：图文介绍、考古发现、历史事件、相关诗词、现代文旅信息
- 检索与筛选：关键词搜索、年代 / 类型 / 城市三维筛选
- 收藏与标签：遗址与文物条目收藏，预置标签与自定义标签分类
- 个人笔记：按遗址记录学习笔记，支持时间正序 / 倒序
- 浏览足迹：记录访问历史，统计学习进度
- 主题路线：按文化主题串联遗址，形成研学路径
- 知识图谱：收藏内容的年代脉络与主题标签可视化
- 桌面卡片：展示收藏、笔记与每日推荐
- 分布式同步：同一账号下的手机 / 平板同步收藏、笔记与足迹

## 环境要求

- DevEco Studio（支持 HarmonyOS 5.0 / API 12 及以上）
- 工程 `compatibleSdkVersion` 为 `5.0.0(12)`，`targetSdkVersion` 为 `26.0.0`
- 分布式同步需要两台真机（手机 / 平板），模拟器仅支持本地数据库能力

## 构建与运行

1. 用 DevEco Studio 打开工程根目录，等待依赖同步完成。
2. 在 `File > Project Structure > Signing Configs` 中勾选自动签名，生成调试证书。
3. 执行 `Build > Clean Project`，再 `Build > Build HAP(s)`。
4. 连接设备后运行 `entry` 模块。

两台设备做分布式同步验证时，需保证：

- 两台设备安装同一签名的安装包
- 登录同一个华为账号
- 连接同一局域网，并在「超级终端 / 多设备协同」中可互相发现
- 首次使用时在两台设备的「我的 → 分布式数据同步」中分别授权开启

## 分布式同步说明

- 基于 `DistributedKVStore` 的 `DEVICE_COLLABORATION` 模式，采用 `PUSH_PULL` 双向同步
- 同步顺序为先拉取合并、再推送、最后再拉取，避免本机旧数据覆盖远端新版本
- 冲突处理采用「最新时间戳优先」：收藏以 `updated_at`（旧数据回退 `created_at`）为版本，笔记以 `updated_at` 为版本
- 删除采用墓碑（tombstone）传播，一端删除后其他设备不会被远端旧数据重新加回
- 笔记跨设备以「遗址 ID + 创建时间」作为逻辑标识，避免本机自增主键冲突
- 推送前比较库中已有版本，较新的远端数据不会被本机旧数据覆盖
- 本地数据变更后 600ms 防抖自动推送，应用回到前台自动同步，退到后台前快速推送
- 未授权或设备不支持分布式能力时自动使用本地模式，不影响其他功能

## 单元测试

测试代码位于 `entry/src/ohosTest`，使用 Hypium 框架。

1. 在 DevEco Studio 中右键 `entry/src/ohosTest`，选择 `Run 'Ohos Test'`。
2. 首次运行前需在工程根目录执行 `ohpm install` 安装 `@ohos/hypium` 依赖。

当前测试覆盖数据模型的同步版本号计算与「最新时间戳优先」判定，后续可按同样结构补充同步合并、墓碑处理等用例。

## 验收清单

- 登录 / 退出登录：退出需二次确认，重新登录后本机数据保留
- 发现页：搜索、三维筛选、推荐、主题路线
- 详情页：收藏、标签编辑、笔记增删改、相关推荐
- 收藏页：按标签筛选、文物与遗址分类、笔记管理
- 我的页：账号详情、学习进度、知识图谱、数据备份与恢复
- 桌面卡片：添加后可展示统计与每日推荐，点击可进入应用
- 分布式同步：两台真机授权后，收藏 / 笔记 / 足迹可双向同步
